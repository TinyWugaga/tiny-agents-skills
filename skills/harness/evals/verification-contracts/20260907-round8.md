    | `E_REGION_STRAY_ID` | gate 區的 KI-nn 只能出現在 `IDs:` 行，散文裡的 ID 不進集合 |
    | residue-deduction | 先扣掉已被 `declared()` 消費的 `` `LABEL` N``，再看殘餘計數 |
    | `E_REGION_CJK_COUNT` | 區內不得以中文數字寫筆數（不受檢查） |
    | `E_REGION_COUNT_FORBIDDEN` | 無 expect 的區不得直接寫「N 筆」 |
    | `E_REGION_COUNT_MISMATCH` | 有 expect 的區，區內每個「N 筆」都要等於推導值 |
    | `gate_ids()` | gate 區恰好一行 `IDs:` 承載集合，不得整區 `findall` |
    | `equation()` | 區內恰好一條算式，不得只取第一條 |
    | `declared()` | `` `LABEL` N`` 逐一解析並與推導值比對 |

    **有效 mutant 必須同時滿足三件事**：測試**跑完並輸出完成摘要**、
    **案例總數等於 baseline**（總數改變則 killed 判定無意義）、
    且**失敗案例確實是因該 guard 的目標行為失效而被殺**——只看「失敗數大於零」不算。
    以「改成 `if False`」停用會造成 crash 或無完成摘要時，該 mutant 無效，
    改用「還原為修正前行為」，並**另外指出該還原確實弱化了目標檢查**
    （例如失敗案例正是斷言該 guard error code 的那幾筆）。
    若某支停用後零案例失敗，那支就是沒有被覆蓋，本條 FAIL。
15. 四支 Python 檔在 **repo 外複本**編譯是否通過（避免在 repo 內產生 `__pycache__`）。
16. **marker 外不得保留未受檢的 ledger 現值。** checker 只解析 marker 內（刻意如此，
    否則歷史段的正確數字會讓錯值矇混過關），因此 marker 外的宣稱依構造偵測不到。
    請人工掃 `KNOWN-ISSUES.md` 與 `STATUS.md` 的 marker 外全部內容，確認**沒有未受檢的
    ledger 現值筆數、集合或分類表**。

    **必須用兩種方法各掃一遍，缺一即本條 FAIL：**
    (a) **逐行 pattern 掃描**；
    (b) **表格掃描**——把 marker 外的每一個連續 Markdown 表格區塊當成獨立一類全數列出，
    附其最近標題與逐塊判斷理由。第 7 次的漏判正是 (a) 命中了發布 gate 表那一列、
    卻在分節判斷時整張表被略過；(a) 命中不等於 (b) 已做。

    **判準看完整上下文**，並同時受下列三條約束：
    * 章節標題、段首的日期限定有效；不得只憑單行的動詞或「數字是否等於現值」就分類。
    * **不得僅因某個 ID 集合恰等於某個 ledger 類別就判違規**——須判斷該處是否
      宣稱完整覆蓋該類別。列舉具體工作項目、且含該類別以外成員的清單不算違規。
    * **僅有父標題日期不足以認定某段為歷史**：須有整段屬當時規劃或當時狀態的
      明確上下文（段內自述「當時」「該批次」「已被取代」，或鄰近數值為舊值）。
      明確封存的歷史計畫使用未來式仍屬歷史。

    這一條無法機械化，請明確寫出你掃了哪些範圍（檔案、行號區間、比對 pattern、
    表格區塊清單）與逐處的判斷理由。
17. 副作用。**可驗子項**：`git status` 筆數是否為 **55**、暫存區是否為空、
