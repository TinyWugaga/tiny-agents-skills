# token-preflight

## 成本判斷

成本以三個可量測 proxy 表達:

- **檔案數**:預期讀取或修改的檔案數。
- **工具呼叫數**:預期需要的工具呼叫次數。
- **行數**:預期產出的程式碼或文字行數。

下節的 scope signals 決定是否必須先估算這些 proxy。需求歧義不是成本訊號;若任務本身
需要澄清,依當前對話的一般執行規則處理。

## 分級

- **小**:單一問題或小段變更,預期 0–2 次工具呼叫。
- **中**:不屬於小,但未達大型任務門檻。
- **大**:任一強訊號,或兩個以上弱訊號。

### 強訊號

- 未指明範圍的 codebase 讀取(例如「看一下我的專案」「掃過整個 repo」)。
- 覆蓋多個模組的重寫、全面重構或批次修改(例如「重構全部」「每一個都改」)。
- 預期工具呼叫數 ≥ 10。
- 預期產出橫跨 ≥ 5 個檔案。

### 弱訊號

- 預期檔案數 ≥ 3,或需讀取整個目錄。
- 預期行數 > 500。
- 預期工具呼叫數為 5–9。
- 任務需要多輪「生成 → 驗證 → 修正」。

只有「大」需要在動手前暫停。使用者未明確要求成本估算時,小或中型任務直接執行,
不提及本 skill、分級或成本判斷;使用者明確要求時,才簡短回報分級與 proxy。

## Pre-flight

大型任務開始前,輸出三項。整份報告以 Markdown source line 計算,不超過 10 行:

1. **規模與成本結構**:說明觸發訊號,並給出 1–2 個 proxy 預估作為 baseline。
2. **更便宜的替代路線**:提供 1–2 個能實際降低成本的方案,例如縮小範圍、先做樣本、
   只交付 diff,或拆成可中止階段。
3. **建議**:明確推薦路線與理由。

然後等待使用者回覆。放行只綁定當前任務與成本邊界;同一任務在相近成本邊界內不重複攔截,
新任務則一律重新分級,不因類型相似沿用先前放行。

## 執行中重新判斷

有 baseline 時,出現任一條件就暫停:

- 實際工具呼叫數達預估的兩倍。
- 實際檔案數或行數比預估多一個量級。

沒有 baseline 時,不得事後補造預估值;途中新出現強訊號就依當下規模重新分級,
若為大型任務,再執行 pre-flight。

暫停時只需回報目前 proxy、新增範圍,以及繼續或縮小範圍的具體選項,不重複完整報告。

## 輸出邊界

- 對話中無法判定任務範圍時,說明缺少哪個成本 proxy 所需的資訊,請使用者補上任務內容後再分級;不猜測量級或數字。
- 只回報量級與成本 proxy,不編造精確 token 數;只有執行環境能可靠顯示 token budget 或已用量時,
  才回報該實際數字。
- 替代路線必須對當前任務可執行,不使用「提供更多資訊」這類無法估算節省量的建議。
- 邊界介於中與大時直接執行,避免頻繁攔截。
- 使用者明確放棄成本控制或以時間優先時,不執行 pre-flight 與執行中成本暫停。
- 放棄成本控制只豁免本 skill 的成本提示,不放寬安全、權限或其他任務限制。
