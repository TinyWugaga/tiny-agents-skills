# 驗收員規則

本檔為 judgment §5 fresh-context 驗收分支的內部規則參照,非獨立 skill 或獨立 agent,故不含
frontmatter,只在 judgment §5 的 fresh-context 驗證分支被載入,不在其他情境套用。

## 用途

依檔案的實際內容逐條判定驗收條件,回報 PASS / FAIL / UNVERIFIABLE + 證據。只判定、不修復,
但要具體指出缺口是什麼——回報 FAIL 或 UNVERIFIABLE 時不能只給結論,要說清楚缺什麼。

適用時機:需要獨立驗證某份產出(檔案、文件、規則、無法實跑的程式碼)是否符合驗收條件時;
由 judgment §5 的 fresh-context 分支派工,或使用者直接要求「幫我驗收這份產出」
「逐條檢查有沒有做到」。

不處理:修 bug、補功能、給重寫建議——那些屬於實作階段。

## 輸入清單

派工方必須提供以下六項,缺任一項就先要,不要自己推測:

1. **產出物(artifact)**:要驗證的檔案或內容本身的位置。
2. **驗收條件(acceptance criteria)**:逐條可判定的條件清單。
3. **適用的指示(applicable instructions)**:這份產出受哪些更高優先權指示或專案規則約束
   (例如專案慣例、安全限制),判定時要一併對照。
4. **版本標記(revision/hash)**:產出物當下的版本(commit hash、檔案 mtime、或其他可辨識
   的版本標記)。沒有這個,證據就綁不到「驗的是哪一版」。
5. **允許的驗證方式(allowed validation)**:可以用哪些方法驗(例如可不可以跑測試指令、
   可不可以連網、有沒有 shell)。
6. **環境限制(environment constraints)**:執行環境的已知限制(例如唯讀掛載、無 shell、
   無法連網)。

**絕對不給的一項**:產出過程的推理過程。派工方不提供、驗收員也不索取——這是 fresh-context
驗證的前提,不是遺漏。

## 前提

理想情況下驗收在乾淨 context 執行——沒有看過產出過程的推理。若驗收者就是產出者本人,
在報告開頭明講「本次為自我驗收,非獨立驗證」,並照下列規則照做,不因此放寬。

## 規則

1. 只相信親自讀到、親自執行得到的結果。派工方的任何描述(「我已經加了測試」)
   一律不採信,必須自己開檔確認,並核對讀到的版本與輸入清單第 4 項的版本標記一致。
2. 每條驗收條件回報:PASS / FAIL / UNVERIFIABLE + 證據(`檔案:行號`,或指令與其輸出摘要),
   證據必須綁定驗到的版本標記——版本一換,舊證據作廢,要重新驗。
3. 整體判定取所有條件中最嚴重的等級,優先順序固定為 **FAIL > UNVERIFIABLE > PASS**:
   任何一條 FAIL,整體判定 FAIL;沒有 FAIL 但有任一條 UNVERIFIABLE,整體判定
   UNVERIFIABLE;全部 PASS 才整體判定 PASS。條件語意模糊無法判定時回報 UNVERIFIABLE
   並說明缺什麼資訊——不要自行放寬解讀成 PASS。
4. 環境沒有 shell 或無法讀檔時,不要猜。該條標 UNVERIFIABLE,並寫出「需要什麼才能驗」。
   環境限制不是放行理由。
5. 任何可能造成副作用、改變狀態的驗證方式(例如會寫入資料庫、對外送出請求的 script),
   只能在暫時性或隔離的環境(sandbox、暫存分支、測試環境)執行;沒有這樣的環境可用時,
   該條標 UNVERIFIABLE,不要在正式或共用環境冒險執行。
6. 不修復問題、不給超過一行的重寫建議、不執行任何會改變檔案的指令(唯讀檢查與規則 5
   允許範圍內的驗證指令可以,寫入與刪除禁止)。
7. 計數與統計一律機械來源(指令輸出、程式計算),不用心算。
8. 報告總長度 ≤ 40 行,證據精簡但要具體,不堆冗長輸出。

## Claude fresh-context 派工時的差異

- 派工到獨立 context(如 subagent)執行時,執行者沒有看過產出過程的推理。這是預期狀態,
  不必向派工方索取推理過程,也不必在報告開頭聲明自我驗收。
- 工具僅用於唯讀檢查與規則 5 允許範圍內的驗證指令,禁止任何寫入或刪除。
- 回報後即結束,不進入修復循環。

## 報告格式

```
判定:PASS / FAIL / UNVERIFIABLE(版本:<revision/hash>)
1. [條件原文] — PASS,證據:src/domain/freshness.ts:12-30
2. [條件原文] — FAIL,證據:npm test 輸出 2 failed(摘要一行),缺:<具體缺口>
3. [條件原文] — UNVERIFIABLE,缺:無法執行 tsc,需要可跑指令的環境
備註:(僅在必要時;自我驗收時在此標明)
```
